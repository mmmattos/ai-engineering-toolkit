# Vector Database

> Design and review vector-database architectures.

# Purpose

Choose vector storage from workload and operational requirements.

# Prompt

## Data Model

Review vectors, metadata, identifiers, tenancy, and versioning.

## Search

Consider metrics, indexing, filtering, hybrid search, and ranking.

## Operations

Consider updates, backups, scaling, latency, cost, and consistency.

# Expected Output

## Assessment

Summarize the design and its main risks.

## Recommendations

Give prioritized practical improvements.

## Validation

Describe how to test the proposed changes.

# Engineering Principles

- Prefer clarity over cleverness.
- Respect the existing architecture and project conventions.
- Make important trade-offs explicit.
- Avoid unnecessary complexity.
