# Clean Architecture

> Design systems with explicit dependency direction and separation between business rules and infrastructure.

# Purpose

Review or design architecture around layers with dependencies pointing toward stable business concepts.

Consider:

- entities and domain rules
- use cases
- interface adapters
- infrastructure
- dependency inversion
- application boundaries
- framework isolation
- testability

Avoid excessive layering and ceremony. The architecture should make business rules easier to understand, test, and evolve.
